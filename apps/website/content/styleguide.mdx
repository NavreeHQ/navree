## Callouts

<Callout type="note">
A plain note: extra context the reader can skip. It can hold `inline code` and [links](/docs/).
</Callout>

<Callout type="tip" title="Run one crate's tests">
Use `cargo test -p navree-validation` while you work on one crate. It builds less and finishes sooner.
</Callout>

<Callout type="warning" title="Commit before you rotate keys">
Changing `APP_KEY` without moving the old key to `app.previous_keys` makes existing encrypted values unreadable.
</Callout>

## Code blocks

A fence with a language gets highlighted. Add `title="..."` for a filename, and `{3-5}` to highlight lines.

```rust title="src/deals/controller.rs" {6-8}
use navree::prelude::*;

#[controller("/deals", version = "1")]
impl DealsController {
    #[patch("/{id}")]
    #[can(Update, Deal, from = "id")]
    async fn update(&self, uow: Uow, deal: Authorized<Deal, Update>) -> Result<Json<DealResource>> {
        Ok(Json(self.deals.touch(&uow, deal).await?))
    }
}
```

Without a title, the bar shows the language:

## Tabs

<Tabs>
<Tab label="PostgreSQL">

A new app runs on TimescaleDB or PostgreSQL. Turn on the `postgres` feature, then point `database.url` at your server.

```sh
cargo add --git https://github.com/NavreeHQ/navree navree --features postgres
```

</Tab>
<Tab label="SQLite">

SQLite is opt-in. Turn on the `sqlite` feature; there is nothing to install.

```toml title="config/app.toml"
[database]
url = "sqlite://storage/app.db?mode=rwc"
```

</Tab>
</Tabs>

## Markdown

### Lists and tables

- Unordered lists use a quiet marker.
- Keep items short.
  - Nested items work too.

1. Ordered lists number themselves.
2. Use them only for real sequences.

| Attribute | Who may call the route |
|---|---|
| `#[public]` | Anyone, signed in or not |
| `#[authenticated]` | Any signed-in user |
| `#[roles("admin", "manager")]` | Users with one of these roles |
| `#[can(Update, Deal, from = "id")]` | Users whose abilities allow updating that deal |

> A blockquote, for quoting a spec or an error message verbatim.
