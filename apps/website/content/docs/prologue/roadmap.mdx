This page describes where Navree is heading. It has no dates: each item ships when it is ready, and the [release notes](/docs/prologue/release-notes/) record what each release brings. If one of these matters to you, [Contributing](/docs/prologue/contributing/) explains how to help.

## Navree 1.0 and the API freeze

0.x releases may still change public APIs; each change is listed in the release notes with what to do about it. Navree 1.0 freezes the public API of every crate in the framework and the ecosystem:

- **Semantic versioning.** After 1.0, a breaking change needs a new major version. Minor and patch releases are safe to take.
- **crates.io.** Every crate is published, so `cargo install navree-cli` and `cargo add navree` replace the Git installs.
- **A minimum supported Rust version** stated for each release, and raised only in minor releases.
- **Upgrade guides** for every major version, with the changes your code needs.

## Long-term support

From 1.0, Navree publishes a support policy: how long each release line gets bug fixes and security fixes, and which major versions are long-term support (LTS) releases with the longest security window. Security fixes are released for every supported line at the same time, with an advisory.

## More drivers

Every module talks to its backend through a driver trait, so new drivers arrive without changes to your code:

- **Redis** for the cache, the queue, sessions, locks and the rate limiter, and as a backplane that lets several `serve` processes share WebSocket broadcasts.
- **More queue backends** alongside the database and memory drivers.

## More starter kits

The [starter kits](/docs/getting-started/starter-kits/) grow with more product shapes and more front ends, each one production-ready from `navree new` and kept current with every release.

## Windows services

`serve`, `queue:work` and `schedule:work` run as Windows services, with the same graceful shutdown they have under systemd, and [Harbor](/docs/tools/harbor/) learns to deploy to Windows Server.

## Security

- **Passkeys.** WebAuthn sign-in alongside passwords and two-factor codes.
- **Revocable access tokens**, for apps that need sign-out to take effect before an access token expires.

## Performance

Performance work continues release by release, focused on the cost of the request pipeline: fewer database round trips per request, less work on requests that don't need it, and no process-wide locks on the hot path. [Performance](/performance/) tracks the numbers.
