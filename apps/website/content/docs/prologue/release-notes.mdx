## Navree 0.1.0

0.1.0 is Navree's first release. It ships the framework (the kernel, the shared contracts, the module crates, the `navree` facade that re-exports them, the attribute macros and the `navree` CLI) together with the first-party ecosystem: tools for monitoring, debugging, queues, administration, deployment and local services, and packages for search, AI, microservices, OAuth, billing and more. Everything shares one version number, is open source under MIT or Apache-2.0 and is free to self-host.

Navree was developed under the working names Keel and, briefly, Navis. You may still meet those names in the repository's design notes from that time.

<Callout type="note" title="Installing from Git">

Install the CLI from the Git repository, and let new apps depend on the repository or a local checkout; [Installation](/docs/getting-started/installation/) shows how.

</Callout>

## The framework

### Foundation

- **`navree-kernel`**: the module graph, a type-keyed dependency-injection container with singleton, request and transient scopes, lifecycle hooks, graceful shutdown and the command runner behind `serve`, `migrate` and every other command. The graph is validated before anything is constructed, and `check --graph` prints it.
- **`navree-macros`**: `#[module]`, `#[injectable]`, `#[controller]`, the route attributes (`#[get]`, `#[post]`, `#[put]`, `#[patch]`, `#[delete]`) and the helper attributes for access, throttling, timeouts, transactions, audit actions and OpenAPI metadata. A route without an access declaration doesn't compile.
- **`navree-contracts`**: the small shared traits and types that let modules cooperate without depending on each other: `Secret<T>`, `RequestId`, `Principal`, jobs and dispatchers, sinks for audit and events, `Broadcaster` and `Clock`.
- **`navree-config`**: typed configuration from `.env`, TOML files and `APP_*` environment variables, validated at boot, with secrets redacted in logs and errors.
- **`navree-log`**: a tracing subscriber with pretty or JSON output, field redaction, per-target levels and rotating log files.

### HTTP

- **`navree-http`**: Axum integration with a default pipeline (request ids, client IP resolution through trusted proxies, panic catching, timeouts, security headers, compression, a per-IP rate limit, body limits, maintenance mode), controllers, deny-by-default route access, per-route throttles, signed URLs, CORS and one JSON error shape for every error (`{ "statusCode", "message", "error" }`, validation failures as 400 with `errors`).
- **`navree-validation`**: `Valid<Json<T>>`, `Valid<Query<T>>` and friends on garde, with one readable message per broken rule and async `unique` and `exists` rules.
- **`navree-api`**: an OpenAPI 3.1 document built from route metadata at `/api/openapi.json`, a docs UI at `/api/docs`, `openapi:export`, and API resource helpers.
- **`navree-session`**: encrypted session cookies with memory and database stores, and CSRF protection for single-page apps that use cookies.

### Data

- **`navree-db`**: SeaORM integration with a unit of work per request (a transaction that commits when the response succeeds), `Repo` with change events, per-module migration sets, seeders, model factories, pagination and the `migrate`, `migrate:rollback`, `migrate:fresh`, `migrate:status` and `db:seed` commands. SQLite by default; PostgreSQL with the `postgres` feature.
- **`navree-cache`**: a memory cache store on moka with `remember`, tags, stale-while-revalidate and atomic locks.

### Security

- **`navree-auth`**: 15-minute JWT access tokens and 30-day rotating refresh tokens with reuse detection, pluggable authentication strategies, `CurrentUser`, registration, password change and reset, email verification, TOTP two-factor authentication with recovery codes, and login throttling.
- **`navree-access`**: roles, permissions and abilities, record checks for `#[can(.., from = "id")]` routes, SQL list filters with `Accessible`, the abilities endpoint that shares the rules with front ends (in the JSON form `@casl/ability` reads), management routes and the `access:role`, `access:grant` and `access:explain` commands.
- **`navree-crypto`**: AES-256-GCM encryption with key rotation, Argon2id password hashing on a bounded blocking pool, token helpers and `key:generate`.
- **`navree-audit`**: an audit log of data changes, sign-ins, permission changes and access denials, with `audit:prune`.

### Workspaces

- **`navree-workspace`**: multi-tenancy at the workspace level, on in the default features. `WorkspaceModule`, the `CurrentWorkspace` extractor, the `Workspaces`, `Members` and `Invitations` services, the `Owner`, `Admin`, `Member` and `Viewer` roles plus your own, workspace-scoped permissions for `navree-access`, resolution from a header, a subdomain, a path prefix or a token claim, and isolation by row, schema or database. See [Workspaces](/docs/workspaces/introduction/).

### Background work

- **`navree-queue`**: database and memory job queues with workers, retries with backoff, unique and delayed jobs, failed-job storage and the `queue:work`, `queue:failed`, `queue:retry` and `queue:flush` commands. Jobs dispatched during a request are queued only if its transaction commits.
- **`navree-events`**: a typed event bus with synchronous and queued listeners.
- **`navree-schedule`**: schedules on cron expressions in UTC, overlap prevention, single-node runs across servers sharing a database, and `schedule:run`, `schedule:work` and `schedule:list`.

### Communication

- **`navree-mail`**: mailables rendered from templates, with SMTP, log, array and failover transports, and queued sending.
- **`navree-notify`**: notifications over mail, the database and broadcasts, with read state.
- **`navree-realtime`**: an in-process WebSocket server that speaks the Pusher protocol, so pusher-js and any Pusher client connects, with public, private and presence channels and a signed relay that lets workers broadcast through the serving process.
- **`navree-view`**: MiniJinja templates for mail and other text.

### Integrations and operations

- **`navree-storage`**: named disks on object_store, streaming, signed temporary URLs and upload checks.
- **`navree-http-client`**: outgoing HTTP with retries, timeouts, an SSRF policy and fakes for tests.
- **`navree-observe`**: `/health/live`, `/health/ready` with per-module checks, and Prometheus metrics at `/metrics`.

### Testing

- **`navree-testing`**: `TestApp` to boot an app or a few modules on a temporary database, an in-process `TestClient` with cookies, `acting_as`, JSON assertions and validation-error assertions, and fakes.

## The ecosystem

### Tools

- **[Lighthouse](/docs/tools/lighthouse/)** (`navree-lighthouse`): application monitoring inside your app, with a dashboard at `/_lighthouse`. Exceptions grouped by fingerprint, slow requests and queries, failed jobs, alerts to email, Slack and webhooks, OpenTelemetry export, and MCP tools so agents can read and resolve issues.
- **[Logbook](/docs/tools/logbook/)** (`navree-logbook`): a local debugging timeline at `/_logbook` of every request, query, job, mail, event, cache call and log line, with filters and request replay. Development only.
- **[Fleet](/docs/tools/fleet/)** (`navree-fleet`): a queue dashboard at `/_fleet` and a worker supervisor (`navree fleet`) with auto-balanced workers per queue, throughput, wait and runtime metrics, retries for failed jobs, pause and continue, and long-wait alerts.
- **[Helm](/docs/tools/helm/)** (`navree-helm`): an admin panel at `/admin` generated from your entities, with fields, filters, actions and metrics per resource (`navree make:resource`). It respects your access rules.
- **[Harbor](/docs/tools/harbor/)**: server provisioning and zero-downtime deployments from the CLI (`navree harbor:provision`, `navree deploy`, `navree deploy:rollback`), configured in `harbor.toml`, with health-checked atomic releases, encrypted secrets, several servers and roles, container images and push-to-deploy from GitHub Actions.
- **[Dock](/docs/tools/dock/)**: local services for development. `navree dock up` starts PostgreSQL, Redis, Meilisearch, Mailpit, MinIO and NATS in Docker or Podman, configured in `dock.toml`.
- **[Navigator](/docs/ai/navigator/)**: the MCP server for your coding agent (`navree mcp`). It lists routes, the module graph and providers, entity schemas, recent logs and the last error, runs read-only SQL and searches the docs for your version.

### Packages

- **[Search](/docs/packages/search/)** (`navree-search`): full-text and vector search over your entities with `#[derive(Searchable)]`, on PostgreSQL full text, Meilisearch, Typesense or embedded Tantivy, with vectors in pgvector or Qdrant and indexes kept in sync through the queue.
- **[AI SDK](/docs/ai/ai-sdk/)** (`navree-ai`): text, structured output, streaming, [agents with tools](/docs/ai/agents-and-tools/), [embeddings and RAG](/docs/ai/embeddings-and-rag/), with provider failover across Anthropic, OpenAI, Google Gemini, Mistral, Ollama and AWS Bedrock, and `AiFake` for tests.
- **[MCP servers](/docs/ai/mcp-servers/)** (`navree-mcp`): expose your app's tools, resources and prompts to AI clients over streamable HTTP or stdio, with per-tool permissions.
- **[Microservices](/docs/microservices/introduction/)** (`navree-micro`): request-response and events between services over TCP, NATS, Kafka, RabbitMQ, Redis Streams and MQTT, and hybrid apps that serve HTTP and messages from one binary.
- **[gRPC](/docs/microservices/grpc/)** (`navree-grpc`) and **[GraphQL](/docs/microservices/graphql/)** (`navree-graphql`): gRPC, gRPC-Web and Connect services on tonic, and GraphQL on async-graphql with dataloaders and subscriptions, both sharing your modules, guards and access rules.
- **[OAuth server](/docs/packages/oauth-server/)** (`navree-oauth`): OAuth 2.1 and OpenID Connect for third-party apps, with PKCE, client credentials, device codes, scopes and consent, and personal access tokens.
- **[Social sign-in](/docs/packages/social-sign-in/)** (`navree-social`): sign-in with Google, GitHub, Apple, Microsoft and more, linked to Navree users.
- **[Billing](/docs/packages/billing/)** (`navree-billing`): subscriptions, trials, usage metering and invoices with Stripe or Paddle, for users or workspaces.
- **[Feature flags](/docs/packages/feature-flags/)** (`navree-flags`): roll features out per user, workspace or percentage, stored in your database.
- **[Webhooks](/docs/packages/webhooks/)** (`navree-webhooks`): signed outgoing webhooks with queue-backed retries and a delivery log, and verified incoming ones.
- **[Localization](/docs/packages/localization/)** (`navree-i18n`): Fluent translations, plurals, locale negotiation and translated validation messages.
- **[Browser testing](/docs/packages/browser-testing/)** (`navree-browser`): drive a real browser from your tests over the Chrome DevTools Protocol.
- **[Starter kits](/docs/getting-started/starter-kits/)**: `navree new <name> --kit saas`, `--kit api` or `--kit micro`. The SaaS kit has a Next.js and shadcn/ui front end with sign-in, workspaces, billing, settings and admin.

### AI-native

- **[Agent skills](/docs/ai/agent-skills/)** for every common task, installed into a project with `navree skills:install`.
- **`AGENTS.md`**: `navree new` writes the project's conventions for coding agents, and a `CLAUDE.md` that points at it.
- **[Docs for agents](/docs/ai/docs-for-agents/)**: `/llms.txt`, `/llms-full.txt` and every docs page as Markdown.

## The CLI

The `navree` binary (crate `navree-cli`) creates apps, generates code and runs the dev loop:

- `navree new <name>`, with `--kit` for a [starter kit](/docs/getting-started/starter-kits/), `--ui next` for a Next.js front end that keeps tokens in httpOnly cookies, and `--navree-path` to choose the Navree checkout.
- `navree make:module <name> [--crud]` and `make:<kind>` generators for controllers, services, entities, migrations, jobs, events, listeners, mail, notifications, policies, commands and tests. Generators never overwrite files; they register what they create at marker comments.
- `navree dev`, which rebuilds and restarts the app when its code changes, and keeps the last good build serving when a build fails.
- The ecosystem's commands: `navree dock up`, `navree deploy`, `navree fleet`, `navree mcp` and `navree skills:install`.
- Every other command is forwarded to the app's binary.

## The reference CRM

`apps/crm-api` is a CRM API built on Navree: companies, contacts, a deals pipeline, activities, a dashboard, users and roles, with live updates over WebSockets, queued notifications, scheduled reminders and an audit log. `apps/crm-web` is its Next.js front end, whose server holds the tokens for the browser. Unit, feature and Playwright end-to-end tests cover both. The [CRM tour](/docs/example-app/crm-tour/) walks through it.

## Performance

A Navree app is one binary that needs a few megabytes at idle and starts in milliseconds. [Performance](/performance/) has Navree's measurements, the workload behind them, the method and how to reproduce them on your own machine.

## Design decisions

- **Token authentication for APIs.** `navree-auth` issues stateless JWT access tokens and rotating refresh tokens, and a backend-for-frontend keeps them in httpOnly cookies for browsers. Cookie sessions with CSRF protection are a separate module, [Sessions and CSRF](/docs/basics/sessions-and-csrf/), for apps that want them.
- **One error shape.** Every error is JSON in Navree's shape, `{ "statusCode", "message", "error" }`, with `errors` for validation failures. Input errors are 400s and CSRF failures are 403s.
- **Real time is built in.** Navree ships an in-process Pusher-protocol server. Processes that don't serve the sockets send their broadcasts to the one that does over a signed HTTP relay.
- **The framework's own crates don't use the macros.** They implement `Module`, `Injectable` and `Controller` by hand, the escape hatch every app can use too. Apps use the macros.
