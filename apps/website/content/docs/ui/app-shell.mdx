The app shell gives every page of an app the same frame: a sidebar of grouped links, a top bar with a sidebar button and the breadcrumb, then the page with its title, actions and body. You define the shell once; each handler takes the `AppShell` extractor and returns an `AppPage`. The preview is drawn 1,100 px wide and scaled to the column; open it on its own to see it at full size, and narrow the window to see the phone layout.

```rust title="src/shell.rs"
use navree::ui::*;

pub fn shell() -> Shell {
    Shell::new("Cloudworks CRM")
        .context("Production")
        .group(
            NavGroup::new("Sales")
                .item(NavItem::new("Deals", "/deals").icon(icons::HANDSHAKE).count("312"))
                .item(NavItem::new("Contacts", "/contacts").icon(icons::USERS)),
        )
        .user(
            UserMenu::new("Gurpreet Singh", "gurpreet@example.com")
                .link("Profile", "/profile")
                .action("Sign out", "/sign-out"),
        )
}
```

## Registering it

Register the shell as a provider, and every handler can take `AppShell`: the shell applied to the request, with the current link marked, the sidebar collapsed or not, and any toast the last page left.

```rust title="src/app.rs"
m.factory(Factory::<Shell>::new(|_| async { Ok(Arc::new(shell())) }))
    .exports::<Shell>();
```

```rust title="src/deals/pages.rs"
async fn show(shell: AppShell) -> AppPage {
    shell
        .page("Sutlej Supply renewal")
        .crumb("Deals", "/deals")
        .actions(Button::primary("Edit").href("/deals/42/edit"))
        .body(Card::titled("Notes").body(Text::new("Two-year term, same price.")))
}
```

A module that serves pages of its own and has no business registering a shell for the whole app, such as a debugging tool, builds its own `Shell` and applies it with `Shell::for_request(path, &headers)`, which does what the extractor does.

## The sidebar

- **Width:** 16 rem open, 3 rem collapsed to its icons. Give every top-level item an icon: the collapsed sidebar shows only that.
- **Collapsing:** the top bar's button and `Ctrl+B` (`Cmd+B` on a Mac) toggle it. The choice is kept in a cookie, so the next page renders the same way with no flash.
- **Phones:** below 768 px it becomes a sheet that slides over the page.
- **Items:** `.count(text)` puts a count at the end, `.sub(item)` nests an item under another, and `.current(true)` marks a link as the current page when several differ only in their query.
- **The user menu:** `.link` adds a page to read; `.action` adds a button that posts, for signing out or switching workspace. It works with JavaScript off and carries the session's CSRF token when there is one.

## Layouts and folding

`Shell::layout` places the navigation: a docked sidebar (the default), `ShellLayout::Inset` with the page in a card beside the sidebar, `ShellLayout::Floating` with the sidebar as a card, or `ShellLayout::Header` with the links in the top bar and each labelled group as a menu. `Shell::collapse` sets what folding does: `Collapse::Icons` (the default), `Collapse::Offcanvas` to slide it away, or `Collapse::Never`. On a phone every layout puts the links in a sheet. See [Themes](/docs/ui/themes/#layouts) for each one drawn.

`Shell::theme_menu()` adds the reader's theme and mode to the top bar; see [Themes](/docs/ui/themes/#the-theme-menu).

## Fetched ahead of a click

Nothing is fetched ahead of a click unless you ask, link by link. `NavItem::prefetch()` fetches a sidebar item when the pointer rests on it or it takes focus, so the page is often there before the click; `NavItem::prefetch_eager()` fetches it as soon as the page is quiet. `AppPage::prefetch_crumbs()` does the same for a page's breadcrumb, and `Shell::prefetch_home()` for the app's name. Each costs a request the user may never need, so ask only for the places users usually go next, and only for pages whose `GET` changes nothing.

## Keyboard and accessibility

<UiA11y>

| Key | Does |
|---|---|
| `Ctrl+B`, `Cmd+B` | Collapses or expands the sidebar. |
| `Tab` | Moves through the sidebar, the top bar, then the page. |
| `Esc` | Closes the sidebar sheet on a phone. |

- The current page's link has `aria-current="page"`; the sidebar button has `aria-expanded`.
- The page is a `<main>` with `id="main"`, and the title is its `<h1>`.
- Every page has a labelled region for [toasts](/docs/components/toast/), and a toast left for the next page is already in it, so it shows with JavaScript off too.

</UiA11y>
