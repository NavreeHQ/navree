`Button` draws a `<button>`, or an `<a>` when you give it an `href`. Its look is a `ButtonVariant` and its height a `Size`, both Rust enums, so a misspelt variant doesn't compile. A page of buttons ships no JavaScript.

```rust
use navree::ui::*;

Button::primary("Create deal").icon(icons::PLUS)
```

## When to use it

Use a button for an action: saving, opening a dialog, submitting a form. Give each view one `Button::primary`, for the action that matters most there.

## Variants

`primary` is the one green button of a view. `Button::new` is the quiet default, `outline` and `ghost` step further back, `destructive` deletes, and `ButtonVariant::Link` reads as a link. `ButtonVariant::DestructiveOutline` is a destructive action that waits beside others, such as "Delete deal" in a row of actions: the danger colour with a faint line of it and no fill, and a thin tint of it on hover. It links the looks stylesheet; the other variants link nothing.

<UiPreview example="button/variants" />

## On the inverse surface

A button inside a part drawn on the inverse surface, such as a card with `CardVariant::Inverse`, reads the flipped colours with no variant of its own. A `primary` button there takes the surface's text colour and the surface's colour as its text: a white button with dark text on a near-black card. An `outline` button has the surface's lines and text.

```rust
use navree::ui::*;

Card::titled("Need 64 or more seats?")
    .variant(CardVariant::Inverse)
    .footer((Button::primary("Request a quote"), Button::outline("Talk to us")))
```

## Sizes

Controls are 32 px tall by default. `Size::Xs`, `Sm` and `Lg` make them 24, 28 and 36 px.

## With an icon

`.icon` puts an icon before the label, `.icon_end` after it. Every icon is a constant in `navree::ui::icons`.

## Icon only

`Button::icon_only` takes the icon and the label a screen reader announces. The label is required, so an icon button can't be nameless.

<UiPreview example="button/icon-only" />

## States

`.disabled(true)` disables a button. On a link it sets `aria-disabled` and takes it out of the tab order, since a link can't be disabled. `.pending(true)` shows the spinner from the first render; the runtime sets the same state on a form's submit button while the form posts. `.loading_text("Saving…")` gives the pending state words: they take the label's place beside the spinner, and the button keeps its width. `.block()` fills the width.

<UiPreview example="button/states" />

## A link that looks like a button

With `.href`, the button is an `<a>`. Use it to go somewhere, not to change something. `.prefetch()` lets the page fetch a link ahead of the click; only use it for a `GET` that changes nothing.

<UiPreview example="button/link" />

`.current(true)` marks the link to the page being shown with `aria-current="page"`, and draws it raised; `.current(false)` writes nothing, so you can pass a comparison. In a [segmented ButtonGroup](/docs/components/button-group/#segmented-links) the current link is the chosen segment.

## Submitting a form

A button's `type` is `button` unless you say otherwise: `.submit()` makes it submit its form and `.kind(ButtonKind::Reset)` reset it. `.named(name, value)` posts a value with the click, for a form with two submit buttons.

In a list that is sorted, filtered or redrawn, give each row its own small form around its button, as a [DataTable](/docs/ui/data-table/)'s row actions do, or use a plain button with a [command](/docs/ui/commands-and-ops/). Don't tie a submit button in every row to one form with `form=`, and don't wrap the rows in a form. In Chromium, every such button that moves makes the form recount its controls across the whole page: with a thousand rows, that is most of a second on a phone for every sort.

<UiPreview example="button/submit" />

`.opens_dialog(id)` and `.closes_dialog(id)` open and close a `<dialog>` with the browser's `command` attribute, with no script; see [Dialog](/docs/components/dialog/). `.on_click(cmd)` runs [commands](/docs/ui/commands-and-ops/) in the browser.

## Keyboard and accessibility

<UiA11y>

| Key | Does |
|---|---|
| `Tab` | Moves focus to the button. A disabled link is skipped. |
| `Enter` | Presses a button, follows a link. |
| `Space` | Presses a button. |

- It is the browser's own `<button>` or `<a>`, with its focus ring, keyboard and role.
- An icon-only button carries `aria-label`; the icon itself is hidden from assistive technology.
- The pending spinner is drawn by CSS over transparent text, so the label is still read.
- With `.loading_text`, the words are read in the label's place while it is pending.

</UiA11y>
