# Navree framework: facts about the real APIs

Collected from the wave integrators of the framework build (2026-10-25). Later notes supersede earlier ones; trust the code over the plan where they differ.

- [W0-integrate-1] KernelError is not #[non_exhaustive]. Besides the plan's variants it has NotImported { module, requested, owner }, AmbiguousProvider { module, requested, owners: Vec<&'static str> }, MissingRequestScope { provider } and DuplicateCommand { name, first, second }. ScopeInversion is { module, singleton, request_scoped }. NotExported means the owner is imported but does not export the key; NotImported means the owner exports it but is not imported.
- [W0-integrate-1] for_root pattern: return a wrapper type whose `id()` is `ModuleId::of::<XModule>()` and whose `is_configured()` is true, and call `m.global()` when the module is global. A plain `XModule` import then reuses the configured instance; two configured instances give ConfiguredTwice. See ConfigModule::for_root in crates/navree-config/src/module.rs.
- [W0-integrate-1] Factory::named and ModuleBuilder::provider_named take `impl Into<Cow<'static, str>>`, so names can come from config at runtime. AppBuilder::override_value replaces only unnamed providers; there is no override_named and no Resolver::lazy_named.
- [W0-integrate-1] Multi-bindings: register with `m.multi(Factory::<dyn HealthCheck>::new(...))` and collect with `ctx.get_all::<dyn HealthCheck>()` or `resolver.get_all`. They are app-wide, ignore visibility, come back in module dependency order, and `get::<T>()` never sees them.
- [W0-integrate-1] Request scope: create one `RequestScope::new()` per HTTP request or job run, and resolve request-scoped providers with `ctx.request_resolver(module_id, scope)`. Resolving one through `AppContext::get` gives MissingRequestScope. A singleton never sees the request scope.
- [W0-integrate-1] AppContext::get, get_named and try_get ignore visibility (service locator). try_get returns None for MissingProvider and logs any other error with tracing::warn. Contributions: `m.contribute(x)` and `ctx.contributions::<X>()`, which returns Contributed { module: ModuleInfo { id, name, global }, value: Arc<X> } in module dependency order. Store `m.module_id()` if you need a resolver for the contributing module.
- [W0-integrate-1] AppBuilder::run_with_args takes arguments without the program name. Built-in commands: `check [--graph]`, and `help`, `list`, `--help` or `-h`. With no command it runs `serve` if a module registers it, otherwise prints help. An unknown command fails before boot. App::shutdown cancels the shutdown token, waits up to shutdown_timeout for tasks on the tracker, then runs the on_shutdown hooks in reverse order, also within shutdown_timeout.
- [W0-integrate-1] Factory errors become KernelError::Construction { provider: <key display>, source }, but a KernelError raised inside a factory, for example by `r.get()?`, keeps its own kind.
- [W0-integrate-1] navree-config: `m.config::<T>()` takes no key argument (it uses T::KEY); the PRD's `.config::<T>("billing")` form does not exist. The section is registered privately; call `.exports::<T>()` to share it. A missing section deserializes from {}. Config::typed::<T>() (deserialize plus validate), section, section_or_default, get_string, get_bool and redacted are available. ConfigModule is global, so modules do not import it, but the app must include ConfigModule (with for_root or plain) or validation fails with MissingProvider for navree_config::config::Config.
- [W0-integrate-1] navree-config test helpers: ConfigSources::new().set(key, json) (above every other source; objects deep-merge) and `.env_vars("APP_", [("APP_X__Y", "v")])` to simulate environment variables. Never use std::env::set_var. Environment values are strings, so a list setting cannot be overridden from the environment unless the module accepts a comma-separated string.
- [W0-integrate-1] navree-contracts: AuditEntry setters are actor, subject(type, id), old_values, new_values, request_id, ip, user_agent and metadata. RequestId::parse_or_generate takes Option<&str>. Backoff serializes with a `type` tag in snake_case. JobEnvelope::of(&job) exists, and Dispatcher::dispatch_later rounds the delay up to whole seconds. `m.job::<J>()` (ModuleBuilderJobsExt) contributes JobRegistration. Secret<T> has no Serialize impl.
- [W0-integrate-1] rustls is ring-only: reqwest uses `rustls-no-provider`, so navree-http-client must call `rustls::crypto::ring::default_provider().install_default()` and ignore the Err, or pass a ring ClientConfig. Any new external crate must avoid aws-lc, openssl, native-tls and cmake, or the lockfile test fails. A new workspace crate needs a row in HIERARCHY in crates/navree/tests/dependency_graph.rs.
- [W0-integrate-1] On Windows, writing files from Python in text mode produces CRLF. The repo's index is LF (core.autocrlf=input), so write files with newline='\n' or use the Edit tool.
- [W1-integrate-1] navree-kernel: `AppContext::downgrade() -> WeakAppContext`, whose `upgrade()` returns `Option<AppContext>`. Use it in any long-lived provider that needs the app after boot (scheduler, queue worker, realtime hub) so it does not keep the app alive.
- [W1-integrate-1] navree-http: register controllers with `m.controller::<C>()` (`ModuleBuilderHttpExt`, which also has `http_layer(GlobalLayer::new(LayerSlot::X, name, |ctx, router| Ok(router.layer(..))))` and `map_error::<E>(fn(&E) -> Option<AppError>)`). Prefer `RouteDef::on(Method, path, handler)` over `RouteDef::new`, so the method and the handler cannot disagree. Every route must declare its access with `.public()`, `.authenticated()`, `.roles()`, `.permissions()` or `.can()`. A guard alone does not count. A route with roles, permissions or can fails the boot unless a `dyn RouteAuthorizer` is registered. A non-public route fails the boot unless a `dyn Authenticator` is registered.
- [W1-integrate-1] navree-http: a path or controller prefix starting with `!` is absolute, with no api_prefix and no version (`!/health/live`, prefix `!/sanctum`). A version of '1' or 'v1' mounts under /v1. Path parameters use axum 0.8 syntax `{id}`; `:id` fails the boot.
- [W1-integrate-1] navree-http: `AppError` (the plan's `From<DbErr>` is impossible) has `headers: Box<HeaderMap>` and `errors: Option<Box<BTreeMap>>`. Build a 422 with `AppError::validation(map)`. Helpers: `from_status`, `csrf_mismatch()` (419), `too_many_requests(d)`, `with_header`, `with_source`, `problem(request_id)`. The problem `type` is the code, e.g. `validation_failed`. Timeouts return 503 with type `request_timeout`.
- [W1-integrate-1] navree-http: `HttpServer::wait_bound().await` returns the bound address when `addr` is 127.0.0.1:0. `build_router(&ctx)` and `route_table(&ctx)` return an error unless HttpModule is in the app. The request extensions hold `AppContext`, `RequestId`, `ClientIp`, `AuthState` and `Arc<RouteMeta>`. The `Arc<RouteMeta>` is added only by the per-route layer; a Uow layer reads it from the response extensions. Metrics are `http_requests_total` and `http_request_duration_seconds`, labelled with method, route (the template, or `unmatched`) and status.
- [W1-integrate-1] navree-http: `UrlSigner` is keyed by `http.signing_key`, else by a key derived from `app.key`/APP_KEY, else by a random per-process key. `ValidSignature::guard()` uses `dyn Clock` when one is registered. CORS origins may be a comma-separated env string. `schema_fn::<T>` puts the schemas T refers to under `x-navree-components`; navree-api must move them into components.schemas.
- [W1-integrate-1] navree-macros: dev-dependencies are now navree-kernel, navree-http, http, tokio and trybuild. Task 13 adds axum and friends. If a key is added to #[module], update `KEYS` and `suggestion()` in src/module.rs and the two unknown-key .stderr snapshots. Regenerate snapshots with TRYBUILD=overwrite.
- [W1-integrate-1] Configurable modules (Http, Logger, Crypto, Cache, View, HttpClient) give the same result for a plain `.module(X)` and for `X::from_config()`: both read the config section, so the app must include ConfigModule. `for_root(opts)` needs no config. CryptoModule reads `app.key`, falling back to top-level `key` (APP_KEY). A missing key does not fail the boot; encryption then returns `CryptoError::MissingKey`.
- [W1-integrate-1] navree-events: `m.listen::<E, L>()` registers provider L and subscribes it. `m.on::<E2, L>()` subscribes a provider that is already registered to another event. Every subscription adds a JobRegistration `events.listener.<E::NAME>.<type_name L>` (use `listener_job_name::<E, L>()`). Queued listeners run inline when no `dyn Dispatcher` is registered. Emitting after shutdown, or after the app is dropped, returns `EventsError::ShutDown`.
- [W1-integrate-1] navree-access engine: `Rules::try_build()` returns `Result<Ability, RuleError>`; `build()` panics on an invalid rule. `Rules::from_permissions` takes the prefix-to-subject map explicitly. `Ability::sql_filter_with(action, subject, &impl SqlColumns)` qualifies columns and binds typed values: UUID columns need `sea_query::Value::Uuid`. The `DateTime` value in conditions is RFC 3339 with microseconds; normalise record timestamps the same way. `Ability` serializes as a CASL rule array.
- [W1-integrate-1] navree-cache: closures passed to `remember` and `flexible` return `Result<T, BoxError>`. TTL arguments are `impl Into<Ttl>` (a Duration, `Ttl::Forever` or `Ttl::Default`). In `flexible(key, fresh, stale, f)`, `stale` is the extra window after `fresh`, not a total. Locks: `locks.lock(name, ttl).acquire().await? -> Option<LockGuard>`, released when the guard is dropped.
- [W1-integrate-1] navree-log: put `LoggerModule::from_config()` right after ConfigModule. `init_for_tests()` exists. navree-db must read `log.slow_query_ms` from Config directly, because L3 cannot depend on navree-log.
- [W1-integrate-1] navree-crypto test helpers: `ConfigSources::new().set("app.key", navree_crypto::generate_key())`; set `hashing.memory_kib=1024` and `hashing.iterations=1` for fast tests. `Hasher::verify` returns Err(InvalidHash) for a malformed stored hash; treat that as a failed login.
- [W1-integrate-1] navree-view: printing an undefined variable is an error (SemiStrict), so template contexts must define every printed field. `Views::from_templates([...])` builds Views without booting an app. `views.exists(name)` checks whether a template exists.
- [W1-integrate-1] navree-http-client: `HttpClient::fake() -> (HttpClient, FakeServer)`, swapped in with `AppBuilder::override_value(Arc::new(client))`. HttpClientOptions has an extra field `max_response_bytes`, so build options with `..Default::default()`.
- [W2-integrate-1] navree-http: new field `HttpOptions.maintenance_except` (default /health/live, /health/ready, /metrics; env `APP_HTTP__MAINTENANCE_EXCEPT=a,b`). Build options with `..HttpOptions::default()`. `RouteDef::transactional()` is informational only.
- [W2-integrate-1] navree-db: `DatabaseModule::for_root(DbOptions{..})`, `from_config()` or plain (section `database`); global. `ctx.get::<Db>()` returns `Arc<Db>`. HTTP handlers take `Uow` as an extractor (one per request; commits when the status is below 400, otherwise rolls back; runs to completion). Jobs and commands use `db.uow(actor, request_id).await` and then commit or rollback. Drop every `Arc<DatabaseTransaction>` from `uow.tx()` before the commit.
- [W2-integrate-1] navree-db: `Repo::<E>::{insert, update, delete, find, find_or_fail, find_for_update}(&uow, ..)` records ChangeEvents. Observers: `m.change_observer::<O>()` (multi-binding `dyn ChangeObserver`). An observer runs inside the transaction and must write through the `tx` it is given (`uow.tx()` errors during commit).
- [W2-integrate-1] navree-db: migrations use `m.migrations(MigrationSet::new("crm").after(["users"]).migration(M))`; seeders use `m.seeder::<S>()` (`dyn Seeder` multi-binding); commands are migrate, migrate:rollback, migrate:fresh [--seed], migrate:status and db:seed [names]. Lock rows only when `uow.lock_for_update()` is true (false on SQLite, where BEGIN IMMEDIATE serialises writers).
- [W2-integrate-1] navree-db: `PageQuery` and `CursorQuery` are extractors (422 on bad input). `paginate(select, &*uow.tx().await?, q)` returns `Page<Model>` (IntoResponse, `.map()`). `cursor_paginate` / `cursor_paginate_desc(select, column, conn, q)` work over a UUID column, and the select must not be ordered. DbErr returned with `?` maps to 404 (RecordNotFound/RecordNotUpdated) and 409 (unique or foreign key). `navree_db::Factory` (model factory) clashes with `navree_kernel::Factory`, so alias one in the prelude.
- [W2-integrate-1] navree-macros: `#[controller("/p", version = "1")]` on an inherent impl, with route attributes `#[get]`, `#[post]`, `#[put]`, `#[patch]`, `#[delete]` (default path "/", `!` for absolute paths). Access is one of `#[public]`, `#[authenticated]`, `#[roles(..)]`, `#[permissions(..)]`, `#[can(Action, Subject[, from = "id"])]`; `#[can]` also accepts string literals. Impl-level helpers go BELOW `#[controller]`. Handlers are non-generic `async fn(&self, extractors..)`. The generated code names `::navree::http::*` and `::navree::access::{ActionMarker, Subject}`, so the facade must have `pub use navree_http as http; pub use navree_access as access;` (navree_access must keep both at its root).
- [W2-integrate-1] navree-testing: `TestApp::builder()` adds `ConfigModule::for_root(hermetic sources)` and plain `HttpModule` itself; never add your own ConfigModule. Use `.config(key, json)`, `.temp_database()` (sets database.url and migrate_on_boot), `.override_value`, and `.fake_auth()` (required before acting_as when the app registers its own `dyn Authenticator`, e.g. navree-auth). Apps built with `crm_api::app(sources)` use `TestApp::from_builder(TestAuthenticator::install(builder))` plus `temp_sqlite_url()`; keep the guard alive. Turn off the per-IP limit in request-heavy tests: `.config("http.per_ip_rate_limit", Value::Null)`.
- [W2-integrate-1] navree-testing: `TestClient` has get, post, put, patch, delete, `csrf_cookie()` and cookie helpers. `TestRequest` has json, form, query, header, bearer, `xsrf()` (sends the raw XSRF-TOKEN cookie value) and send. `TestResponse` has `assert_status(u16)`, `assert_json_path("data.0.x", json!)` and `assert_problem(status, "code" | None)`, all chainable, plus json_value, text and set_cookie. Requests come from 127.0.0.1 with `Accept: application/json` and Origin set to the first CORS origin.
- [W2-integrate-1] navree-observe: `ObserveModule::for_root(ObserveOptions{metrics, metrics_token})` or from_config (section `observe`). The routes are /health/live, /health/ready and /metrics. Readiness picks up every `dyn HealthCheck` multi-binding (database and storage register theirs). The Prometheus recorder is process-wide: tests should set `metrics: false`, or assert with >= rather than exact counts.
- [W2-integrate-1] navree-api: `ApiModule` (imports HttpModule; section `api`) serves /api/openapi.json and /api/docs and adds the command `openapi:export [path]`. Use `m.api_schema::<T>()` for types that appear only inside generics. Helpers: `ApiResource` / `resource_json` (adds `__type`), `mask_fields`, `Problem`. The `cookie` security scheme reads its cookie name from config key `session.cookie`.
- [W2-integrate-1] navree-mail: `MailModule::for_root(MailOptions{transport: TransportConfig::Array, ..Default::default()})`. The app MUST also include ViewModule. `Mailer::send` and `Mailer::queue(&TemplateMail::new(to, subject, template).context(json!))` both exist; queue sends at once when no `dyn Dispatcher` is registered. The job name is `mail.send` (SendMailJob). In tests, read sent messages with `mailer.array_transport().unwrap().sent()`.
- [W2-integrate-1] navree-realtime: `RealtimeModule::for_root(RealtimeOptions{key, allowed_origins, ..Default::default()})`. Channel authorizers: `m.channel("users.{id}", |principal, params, ctx| Box::pin(async {..}))`, with patterns written without the private-/presence- prefix. `realtime.broadcast(["private-crm.deals"], "deal.updated", json!(..))` is SYNC; the async form is the `Broadcaster` trait method, and `dyn Broadcaster` is exported. /broadcasting/auth is `.authenticated()`, so the app needs a `dyn Authenticator`; it is also subject to CSRF in navree-session.
- [W2-integrate-1] navree-storage: `StorageModule::for_root(StorageOptions{default, disks: {name: DiskConfig::Local{root, public_url}|Memory}, base_url})`; build struct literals with `..Default::default()`. Use `Storage::disk(name)` or `default_disk()`, and `Disk::{put, put_stream, get, get_stream, exists, delete, list, size, url, temporary_url}`. Uploads go through `store_upload(field, &disk, dir, UploadRules::new(max, ["image/*"]))`, which returns 413 or 422. Temporary URLs are signed with a key derived from app.key: set APP_KEY so links survive restarts.
- [storage-s3] navree-storage: drivers `s3` (AWS, MinIO, R2, Spaces; `S3Config::new(bucket).region().endpoint().credentials().path_style().prefix()`), `gcs` (`GcsConfig`) and `azure` (`AzureConfig`) behind crate features `s3`/`gcs`/`azure` (facade `storage-s3` in full, `storage-gcs`/`storage-azure` opt-in), on object_store's `*-base` features with ring + reqwest (never `aws`/`gcp`/`azure`, which pull aws-lc). `Disk::temporary_url` is now async (provider-signed on cloud disks). `disk.presigned_put(path, ttl, &rules).content_type(t).size(n).await` -> `PresignedUpload {disk, path, method, url, headers, expires_at}`; `disk.accept_upload(path, &rules)` sniffs and deletes a bad file (`StorageError::Rejected`, 400/413 through `?`, with codes from `UploadRejection::code()`: `file_type_not_allowed`, `missing_content_type`, `invalid_content_type`, `empty_file`, `payload_too_large`; an invalid path is `invalid_file_path`, a wrong size on the local upload route `upload_size_mismatch`). `upload_path(dir, type)`. `Storage::sync(from, to, &SyncOptions)` and the `storage:sync` command. `Disk::metadata`/`files` give `FileMeta {path, size, last_modified}`. Tests: the conformance suite in `tests/storage/conformance.rs` runs on memory, local, an in-process SigV4-checking S3 server and MinIO (`NAVREE_TEST_S3_URL=http://key:secret@127.0.0.1:9000/bucket`).
- [W3-integrate-1] navree-db: `Uow::current()` gives the task's unit of work (the request's while a handler runs, and inside `Db::transaction` or `uow.scope(fut)`). Spawned tasks do not inherit it. Check `uow.is_finished().await` before writing through it. Use `uow.same_as(&other)` to compare handles.
- [W3-integrate-1] navree-queue: in handlers, plain `queue.dispatch(job)` and `dyn Dispatcher` now join the request transaction; `dispatch_in` is no longer required on SQLite. A job dispatched by a request that ends with status 400 or above is not queued. QueueFake records immediately. Install the fake with `override_value(Arc::new(fake.queue()))`, or `override_value(fake.dispatcher())` when QueueModule is absent. In tests, run queued work with `ctx.get::<Queue>().run_pending()`. Every Queue method returns Result<_, QueueError>. `retry` accepts "all" or an id. `queue:work` flags: --queue a,b, --once, --stop-when-empty, --max-jobs N.
- [W3-integrate-1] navree-notify: `NotifyOptions { queue, routes }`; build it with `..NotifyOptions::default()`. In handlers, `send` now behaves like `send_in` with the request Uow. The user Notifiable must return `notifiable_type()` == `navree_notify::USER_NOTIFIABLE_TYPE` ("user") and `notifiable_id()` == the UUID's to_string(). Without a `dyn Authenticator`, set notify.routes=false. Broadcasts go out as event `notification.created` with payload {id,type,data,read_at,created_at}.
- [W3-integrate-1] navree-access: use `AccessOptions { abilities: fn(&AbilityCtx, &mut Rules), super_admin_role: Option<String> }`. In the abilities fn call `ctx.grant_permissions(rules)`; one-argument `from_permissions` does not exist. Build AbilityCtx with `for_user`/`guest` or `..Default::default()` (it has a 4th field, `permission_subjects`). Import `AccessModule::for_feature::<E>()` per entity (E: EntityTrait + Subject) so `can(.., from = "id")` can load records; use `for_subject::<S>()` for prefix-only subjects. Rule fields and conditions name DB columns. Permission strings are `<prefix>.<action>` (`*` = manage). A registered prefix maps to its subject; an unregistered prefix stands for itself (`audit.read` -> can read `audit`), for both route `.permissions()` and token abilities. Super-admin appends `can manage all` last.
- [W3-integrate-1] navree-access AccessService: writes take `&Uow` first, e.g. `create_role(&uow, name, desc)`, `grant(&uow, role, perm)`, `assign_role(&uow, user, role)`, `sync_user_roles`, `sync_role_permissions`. Reads use the pool: `roles_of`, `permissions_of`, `role`, `roles`, `version`. Commands: `access:role <name> [desc]`, `access:grant <role> <perm>`, `access:explain <user> <action> <subject> [id]`. Routes: `GET /api/me/abilities`, whose ETag is `"<user>-<version>-<fnv>"`; `/api/access/roles...` requires `roles.manage`.
- [W3-integrate-1] navree-access extractors: `Authorized<E, A>` gives `into_inner`, `check_fields(&[&str])` (403) and Deref. `Accessible<E, A>::apply(select)`. Also `Abilities(Arc<Ability>)` and `CurrentAccess`. Action markers are Read, Create, Update, Delete, Manage; constants are READ..MANAGE and ALL.
- [W3-integrate-1] navree-session: plain `.module(SessionModule)` and `from_config()` read section `session`; `for_root(SessionOptions{..Default::default()})` takes options directly. It needs CryptoModule (APP_KEY), plus DatabaseModule when `session.store = "database"`. `secure` defaults to true, so plain-HTTP dev needs session.secure=false. `same_site` is an enum (strict, lax, none). Session API: get::<T>, insert (Result; `_token` is reserved), remove, contains, regenerate, invalidate (sets a fresh CSRF token), flush, csrf_token. CSRF applies to every method except GET, HEAD, OPTIONS and TRACE when the session cookie is present and there is no Bearer token; cross-site requests without a session from origins not in http.cors.allowed_origins also get 419. For navree-auth: read `parts.extensions.get::<Session>()` and `auth.user_id`; on login call regenerate then insert; on logout call invalidate. Do not fall back to the session when a Bearer token is invalid.
- [W3-integrate-1] navree-validation: extractors are `Valid<Json<T>>`, `Valid<Query<T>>` and `Valid<Form<T>>`, and the same three under `ValidAsync<..>` (T: AsyncRules). Apps need `garde` as a DIRECT dependency, because the derive emits ::garde paths. Use `AsyncRule::unique(field, table, col, value, ignore_id)` with `.ignore_path_param("id")`, and `AsyncRule::exists(..)`; a None value skips the rule. Write `#[garde(custom(confirmed(&self.password_confirmation)))]`. `ValidationModule::for_root()` takes no args; `with_options(ValidationOptions{messages, attributes})` overrides messages. A wrong Content-Type gives 415. For a login 422, build `ValidationErrors` and call `.into_app_error()`.
- [W3-integrate-1] navree-audit: `AuditModule::from_config()` (section audit) needs DatabaseModule and, since `routes` defaults to true, a `dyn RouteAuthorizer` (navree-access). Otherwise set audit.routes=false. `dyn AuditSink`/`AuditLog::record` is queued to a background writer, so it never blocks on SQLite; tests must call `ctx.get::<AuditLog>().await?.flush().await` before reading rows. `record_in(&uow, entry)` writes inside the transaction. Data rows use actions like `deal.updated` with subject_type `Deal`. Build AuditOptions literals with `..Default::default()`. Command: `audit:prune [--days N]`.
- [W3-integrate-1] navree-schedule: `ScheduleModule::for_root()` (or plain) needs DatabaseModule. Register with `m.schedule(|s| { s.job(MyJob).daily_at("08:00"); s.command("audit:prune", &[]).daily_at("03:00").without_overlapping(); })`; the closure needs a block. `job` takes a value, not a type parameter. `task(name, |ctx| async {..})`. Commands: `schedule:run`, `schedule:work`, `schedule:list`. RunStatus and SkipReason are available for tests.
- [W3-integrate-1] Dependency graph: a dev-dependency may target any navree crate in a lower layer (e.g. navree-auth dev-depending on navree-view or navree-mail). A new workspace crate still needs a HIERARCHY row.
- [W4-integrate-1] Error format (navree-http): `AppError::body() -> serde_json::Value` replaces `problem(request_id)`. `navree_http::ERROR_CONTENT_TYPE` ("application/json") replaces `PROBLEM_JSON`, which is gone. `AppError` keeps `code` and `title`: `code` is not rendered; `title` is the default `message`. `message` is the detail if set, otherwise the title; when `errors` is non-empty it is all field messages flattened in field order. `error` is the reason phrase from `status.canonical_reason()`.
- [W4-integrate-1] `from_status` titles are now reason phrases: 401 "Unauthorized", 403 "Forbidden", 429 "Too Many Requests", 500 "Internal server error". `AppError::validation(map)` is 400 with code `validation_failed`. `csrf_mismatch()` is 403 with code `csrf_token_mismatch` and message "Invalid CSRF token". Timeouts are 503 with message "The server did not finish the request in time." Axum's 422 rejections become 400. There are no 422 or 419 responses anywhere.
- [W4-integrate-1] navree-testing: use `assert_error(status, "msg")` or `assert_error(status, None)`; it checks the status, `application/json`, `statusCode`, `error`, `message` and `X-Request-Id`, and a message matches either the string or one element of the array. `assert_validation_error("field")` checks for a 400 and a non-empty `errors[field]`. `assert_problem` is `#[deprecated]`, so calling it fails `clippy -D warnings`.

An HTTP layer in `LayerSlot::Session` captures headers and bodies (bodies of known size up to 4 MiB) and marks ignored request ids; it is applied only when Logbook is on (the factory fills a `OnceLock` the layer reads). The SQLite store uses sqlx 0.9 directly (`AssertSqlSafe` for built SQL, statement logging off so its own queries never become log entries); `PRAGMA user_version` 1, recreated on a mismatch.
- [error-codes] Every error body carries a machine-readable `code` after `error`: `{statusCode, message, error, code, errors?}`. `AppError.code` is a public `String`; `AppError::new(status, code, title)` takes it, `from_status` derives it (reason phrase in snake case, `unauthenticated` for 401, `internal_error` for 500), and `.with_code("snake_case")` sets an app's own. Framework codes are constants in `navree_http::codes` (`ALL`, `is_valid`); new constructors `AppError::invalid_filter`, `two_factor_required`, `limit_reached`, `demo_read_only`. Give every refusal a user reads its own code (modules do: auth, workspace, access, social, billing, webhooks; the table is on docs/basics/errors). `http.errors.code = false` (`APP_HTTP__ERRORS__CODE`) leaves the member out of responses; `AppError::body()` always includes it. Tests: `assert_error_code(status, code)` in navree-testing. The OpenAPI `HttpError` schema has an optional `code`. GraphQL keeps its own upper-snake `extensions.code` per status.
- [error-codes merge] Crates merged on main since the branch started now carry the code too: navree-micro's `RemoteError::code()` reads a reply's `code` and `to_app_error()` keeps it (an app code such as `email_taken` crosses services unchanged); navree-ai's tool results for 5xx (`"The tool failed"`) include the error's `code`; the ai, microservices, search, localization and helm docs pages show `code` in their error bodies.
- [M3-3 fleet] navree-fleet is L7 (allowed: kernel, contracts, config, telemetry, http, events, view, db, observe, queue, access); facade feature `fleet` is in `full`. Core hooks: navree-queue gained introspection (`Queue::status` -> `QueueStatus`, `pending_jobs(&PendingQuery)`, `pending_job`, `failed_job`, `forget`) and supervision (`Queue::work_supervised(opts, Supervision { workers, stop, hooks })`, `WorkHooks::{may_reserve, attempted}`, `Attempt`, `AttemptOutcome`, re-exported `CancellationToken`); navree-observe gained `MetricsCollector` (`dyn MetricsCollector` multi-bindings run before `/metrics` renders, 2 s each, `COLLECT_TIMEOUT`).
- [M3-3 fleet] Doc deviations, now in the page: workers run `fleet:work` (not `queue:work`; queue cannot know Fleet's flags), commands over stdin (`pause`/`continue`/`stop`), reports as `@fleet {json}` stdout lines. The dashboard is a navree-view page plus a script (no SPA build, no navree-dashboard kit yet): it signs in through navree-auth's `{api_prefix}{auth.routes_prefix}/login` (2FA too) and keeps bearer tokens in the tab's session storage, not an encrypted cookie with CSRF; API routes check `can(view|operate, Fleet)`. Dashboard needs AuthModule + AccessModule (not CryptoModule). Workload = (waiting + running) x 5-minute average runtime (1 s assumed), capped per queue at `ceil(active / concurrency)`. `simple` needs `max_processes >= queues`. Recent jobs are stored per heartbeat batch (3 s), not per snapshot. Lighthouse integration claims removed (no Lighthouse crate yet).
- [M3-3 fleet] Behaviour: pause and terminate live in `fleet_state` (terminate is a token; masters started later keep running). Long-wait events are deduplicated across masters with a conditional update on `fleet_state` (`long_wait:<queue>`). A master's loop logs database errors and keeps its workers running. `JobRecorder` (telemetry sink) records only once armed by a worker. Tests: `navree_fleet::testing::FakeSpawner`, `InProcessSpawner`, `MasterSettings` for fast ticks; `tests/processes.rs` (harness = false) spawns the test binary itself as real workers (works on Windows).
- [M3-3 fleet merge] Main's public `QueueStore` (custom drivers such as navree-redis) arrived while Fleet was built, and the trait has no introspection methods. With a custom driver, `Queue::status` counts every pending job as waiting (`pending_count`; no delayed, running or oldest wait), `pending_jobs`/`pending_job` find nothing, `failed_job` searches `failed()`, and `forget` returns `QueueError::Store` (no single-job delete). Adding these to `QueueStore` (with defaults) and implementing them in navree-redis is open.
