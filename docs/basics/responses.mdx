A handler returns anything that implements `IntoResponse` (`navree::http::IntoResponse`). Navree adds a few response types of its own (`Created`, `NoContent`, `Page<T>`) and a pattern for API resources: structs that give your models a stable, documented JSON shape. This page covers all of them, plus headers, file downloads and streamed bodies.

## Returning JSON

Wrap any `Serialize` value in `Json`. Most handlers return `Result<Json<T>>`, where `Result` is the prelude's `navree::Result`, whose error type is [`AppError`](/docs/basics/errors/):

```rust title="src/companies/controller.rs"
use navree::prelude::*;
use uuid::Uuid;

#[injectable]
pub struct CompaniesController;

#[controller("/companies", version = "1")]
#[authenticated]
impl CompaniesController {
    #[get("/{id}")]
    async fn show(&self, uow: Uow, Path(id): Path<Uuid>) -> Result<Json<CompanyResource>> {
        let company = Company::find_or_fail(&uow, id).await?; // a 404 when missing
        Ok(Json(company.to_resource::<CompanyResource>()))
    }
}
```

The response is `200 OK` with `Content-Type: application/json`. `Json` is navree-http's, in `navree::http` and the prelude; the same type reads JSON request bodies.

For a one-off shape, `serde_json::json!` is enough:

```rust
#[get("/stats")]
async fn stats(&self) -> Json<Value> {
    Json(json!({ "companies": 42, "open_deals": 7 }))
}
```

Other types work too: a `String` or `&'static str` is a `200` with `text/plain; charset=utf-8`, and a bare `StatusCode` is an empty response with that status (an error status gets the [error format](/docs/basics/errors/) body).

Responses are compressed with gzip when the client accepts it (`Accept-Encoding`), except `text/event-stream`, images other than SVG, gRPC other than gRPC-Web (media types in any case), responses that already have a `Content-Encoding` or a `Content-Range`, partial responses (206: a `multipart/byteranges` body has no `Content-Range` of its own), responses with `Cache-Control: no-transform`, routes that opt out, statuses without a body (204, 205, 304) and bodies under 32 bytes. A compressed response loses its `Content-Length` and `Accept-Ranges`, and a strong `ETag` becomes a weak one (`"v1"` becomes `W/"v1"`), because its bytes are not those the tag promised; `If-None-Match` still matches it. A `HEAD` response has the headers of the `GET` response, compressed or not, and no body, and a 304 carries `Vary: accept-encoding` like the 200 it stands in for (unless the route opts out or the response says `no-transform`). A streamed body stays a stream: whatever the handler has sent reaches the client as soon as the handler waits. Turn compression off with `http.compression = false`. With the UI toolkit, pages and ops answers may go out in brotli instead (see [the UI overview](/docs/ui/overview/)); the same opt-outs hold for it: a route that opts out, a response with `Cache-Control: no-transform` and `http.compression = false` leave the body uncompressed by either.

### Compression and secrets (BREACH)

Compression makes a body shorter when it repeats itself, so its length says something about its content. A page that holds a secret (a CSRF token, an API key) and also reflects something from the request (a search term) can give the secret away: an attacker who can make a signed-in user's browser send requests, and can see the length of the responses on the network, guesses the secret a character at a time and keeps the guesses that come back shorter. TLS hides the bytes, not their length.

A response is exposed when all of these hold: it is compressed, it has a secret and reflected input in one body, the secret is the same from one response to the next, and the session cookie goes along on a cross-site request. Helm's session cookie is `SameSite=Strict`, which stops that last step. Your own cookies may not be, so for a route that fits, do one of these:

```rust
// On the route: its responses are never compressed.
#[get("/search")]
#[no_compression]
async fn search(&self, query: Query<Search>) -> Html<String> { /* .. */ }

// On a hand-written route.
RouteDef::on(Method::GET, "/search", search).no_compression();

// On one response, from anywhere.
([(header::CACHE_CONTROL, "no-transform")], page)
```

Each of these holds for every compressor of the app: the HTTP pipeline's gzip and the UI toolkit's brotli for pages and ops answers.

Keeping the secret out of pages that reflect input, or masking it with fresh random bytes on each response, works too. The session's CSRF token is masked that way already wherever Navree writes it into a body (Navree UI's forms, Helm's pages, native screens); in markup of your own, write `navree::http::csrf::page_token(&session.csrf_token())`, which the check takes as it takes the token (see [the token in pages](/docs/basics/sessions-and-csrf/#the-token-in-pages)). The `XSRF-TOKEN` cookie holds the token as it is: a header carries it, not a body. JSON APIs that authenticate with a bearer token in a header aren't exposed: a cross-site request can't add the header.

## Status codes

### Created and no content

`Created(location, body)` answers `201 Created` with a `Location` header and a JSON body. `NoContent` answers `204 No Content`. The CRM's deals controller uses both:

```rust title="crm-deals/src/controller.rs"
#[post("/")]
#[can(Create, Deal)]
async fn store(
    &self,
    uow: Uow,
    CurrentUser(user): CurrentUser,
    Abilities(ability): Abilities,
    Valid(Json(input)): Valid<Json<CreateDeal>>,
) -> Result<Created<DealResource>> {
    let deal = self.deals.create(&uow, &ability, user.id, input).await?;
    Ok(Created(format!("/api/v1/deals/{}", deal.id), deal))
}

#[delete("/{id}")]
#[can(Delete, Deal, from = "id")]
async fn destroy(&self, uow: Uow, deal: Authorized<Deal, Delete>) -> Result<NoContent> {
    self.deals.delete(&uow, deal.into_inner()).await?;
    Ok(NoContent)
}
```

A `Location` that isn't a valid header value turns the response into a 500.

### Any other status

Return a tuple of a `StatusCode` (from the `http` crate, which your app adds to its dependencies) and the body:

```rust
use http::StatusCode;

#[post("/import")]
async fn import(&self) -> (StatusCode, Json<Value>) {
    (StatusCode::ACCEPTED, Json(json!({ "queued": true })))
}
```

Error statuses come from `AppError`, so they share Navree's JSON error shape; see [errors](/docs/basics/errors/). To document a route's status in the OpenAPI document, add `status = 201` to its `#[api(...)]` attribute ([OpenAPI](/docs/digging-deeper/openapi/)).

## Headers

Put an array of header pairs before the body:

```rust
use http::header::{CACHE_CONTROL, ETAG};
use navree::http::response::{IntoResponse, Response};

#[get("/{id}/summary")]
async fn summary(&self, Path(id): Path<Uuid>) -> Response {
    (
        [(CACHE_CONTROL, "private, max-age=60"), (ETAG, "\"v1\"")],
        Json(json!({ "id": id })),
    )
        .into_response()
}
```

A `HeaderMap` works in the same place when the headers are built at run time.

<Callout type="note" title="impl IntoResponse in controllers">

Controller methods take `&self`, and in Rust 2024 a returned `impl Trait` captures that borrow, which the generated handler can't allow. Return a concrete type, `Response` (with `.into_response()`), or write `impl IntoResponse + use<>`.

</Callout>

Navree adds its own headers to every response: `X-Request-Id`, the [security headers](/docs/basics/cors-and-security-headers/) and, for allowed origins, the CORS headers. A security header you set yourself replaces the default one. The full response of the example above looks like this:

```http
HTTP/1.1 200 OK
content-type: application/json
cache-control: private, max-age=60
etag: "v1"
vary: accept-encoding
x-content-type-options: nosniff
x-frame-options: DENY
referrer-policy: no-referrer
strict-transport-security: max-age=31536000; includeSubDomains
content-security-policy: default-src 'none'; frame-ancestors 'none'; base-uri 'none'
x-request-id: 01a17749fe6c725e935830d1c31aba93
```

## HTML and redirects

`Html` wraps a body and sets `Content-Type: text/html; charset=utf-8`. `Redirect` answers with a status and a `Location` header: `Redirect::to` is a 303 See Other (the client follows it with a `GET`), `Redirect::temporary` a 307 and `Redirect::permanent` a 308 (the client repeats the method and the body):

```rust
use navree::http::response::{Html, Redirect};

#[get("/status")]
#[public]
async fn status_page(&self) -> Html<&'static str> {
    Html("<!doctype html><title>Status</title><p>All systems normal.</p>")
}

#[post("/{id}/archive")]
#[authenticated]
async fn archive(&self, Path(id): Path<Uuid>) -> Redirect {
    // ...
    Redirect::to("/archive")
}
```

A `Location` that can't be a header value, such as one with a newline, turns the response into a 500. The default `Content-Security-Policy` allows a page no styles or scripts; a route that serves a real page sends its own, as [security headers](/docs/basics/cors-and-security-headers/#changing-a-header-for-one-response) shows.

## API resources

Returning a database model as JSON ties your API to your table: a renamed column or a new private field changes what clients see. An API resource is a separate struct that decides the shape, so the table and the API can change independently.

### The resource pattern

The CRM gives every model a `*Resource` struct that implements `Resource<Model>`, builds it from a record with `to_resource::<R>()`, and returns it from every route of that model:

```rust title="src/companies/resource.rs"
use chrono::{DateTime, Utc};
use navree::api::ApiResource;
use navree::openapi::ToSchema;
use navree::orm::attributes::Resource;
use navree::orm::Record;
use serde::Serialize;
use uuid::Uuid;

/// A company as the API returns it.
#[derive(Clone, Debug, Serialize, ToSchema)]
#[schema(as = Company)]
pub struct CompanyResource {
    /// Always `"Company"`: the subject type front ends check permissions with.
    #[serde(rename = "__type")]
    #[schema(example = "Company")]
    pub resource_type: &'static str,
    pub id: Uuid,
    pub name: String,
    pub domain: Option<String>,
    pub owner_id: Uuid,
    pub created_at: DateTime<Utc>,
}

impl ApiResource for CompanyResource {
    const TYPE: &'static str = "Company";
}

impl Resource<Company> for CompanyResource {
    fn from_record(company: &Record<Company>) -> Self {
        CompanyResource {
            resource_type: "Company",
            id: company.id,
            name: company.name.clone(),
            domain: company.domain.clone(),
            owner_id: company.owner_id,
            created_at: company.created_at,
        }
    }
}
```

```json title="GET /api/v1/companies/0192f0c1-..."
{
  "__type": "Company",
  "id": "0192f0c1-7b3a-7c51-9a4e-5d2f8e1b6a90",
  "name": "Agra",
  "domain": "agra.com",
  "owner_id": "0192f0c1-0000-7000-8000-00000000000a",
  "created_at": "2026-10-25T09:12:44Z"
}
```

The pieces of the pattern:

- **`Resource<Model>`** builds the resource from a record: `company.to_resource::<CompanyResource>()`, or `page.map(|company| company.to_resource::<CompanyResource>())` for a page. A model that names its resource with `#[model(resource = CompanyResource)]` also has `company.resource()`; see [ORM serialization](/docs/orm/serialization/#api-resources).
- **`__type`** carries the subject type, so a front end using `@casl/ability` can check permissions on plain JSON objects (`detectSubjectType: (o) => o.__type`). The name matches the subject your [access rules](/docs/security/authorization/) use.
- **`ToSchema`** with `#[schema(as = Company)]` puts the resource in the [OpenAPI document](/docs/digging-deeper/openapi/) under a clean name; reference it with `#[api(response = CompanyResource)]`.
- **Embeds.** The CRM's `DealResource` embeds `company`, `contact` and `owner` objects. The list route loads them with `Deal::query().with_all(DealResource::EMBEDS)`: one query per kind of embed for a whole page of deals, never one per row.
- **Derived fields.** `DealResource` adds `probability`, computed from the stage, which the table doesn't store.

### Resource helpers

`navree::api` has three helpers for resources built at run time:

```rust
use navree::api::{ApiResource, mask_fields, resource_json};

#[derive(Serialize)]
pub struct ProjectResource {
    pub id: Uuid,
    pub name: String,
    pub budget_cents: i64,
}

impl ApiResource for ProjectResource {
    const TYPE: &'static str = "Project";
}

pub fn project_json(project: &ProjectResource, readable: Option<&[String]>) -> Value {
    mask_fields(resource_json(project), readable)
}
```

- `resource_json(&resource)` serializes the resource and adds `"__type": TYPE`.
- `mask_fields(value, Some(&fields))` keeps only the listed top-level fields, plus `id` and `__type`, in an object or in every object of an array. `None` keeps everything. Pass the fields the user may read, for example from the ability's `permitted_fields`.

With `readable` set to `["name"]`, `project_json` returns `{"__type": "Project", "id": "...", "name": "Apollo"}`.

The CRM uses typed resource structs rather than these helpers, because typed structs also give it OpenAPI schemas.

## Paginated responses

`Page<T>` is a page of results. Return it directly; it serializes as `data` plus `meta`:

```rust
#[get("/")]
async fn index(&self, uow: Uow, page: PageQuery) -> Result<Page<CompanyResource>> {
    let page = Company::query()
        .order_by(Company::NAME)
        .paginate(&uow, page)
        .await?;
    Ok(page.map(|company| company.to_resource::<CompanyResource>()))
}
```

```json title="GET /api/v1/companies?page=2&per_page=15"
{
  "data": [
    { "__type": "Company", "id": "0192f0c1-...", "name": "Gulati" }
  ],
  "meta": { "current_page": 2, "per_page": 15, "total": 16, "last_page": 2 }
}
```

`PageQuery` reads `?page=` and `?per_page=` (defaults 1 and 15; `per_page` is capped at 100) and `Page::map` turns models into resources without touching `meta`. Cursor pagination returns a `CursorPage<T>` instead: `{"data": [...], "next_cursor": "...", "prev_cursor": null}`. Both are covered on the [pagination page](/docs/database/pagination/).

<Callout type="note" title="Pages in the OpenAPI document">

`Page<T>` doesn't implement `ToSchema`, so `#[api(response = ...)]` can't name it. To document a page, the CRM declares a struct per page (`CompanyPage { data: Vec<CompanyResource>, meta: ... }`) and names that instead.

</Callout>

## File downloads

A download is a body with a `Content-Disposition` header. The CRM's contact export builds a CSV in memory:

```rust title="crm-companies/src/contacts/export.rs"
use http::header::{CONTENT_DISPOSITION, CONTENT_TYPE};
use navree::http::response::{IntoResponse, Response};

pub fn csv_response(contacts: &[ContactResource]) -> Result<Response> {
    let body = contacts_csv(contacts).map_err(AppError::internal)?;
    Ok((
        [
            (CONTENT_TYPE, "text/csv; charset=utf-8"),
            (CONTENT_DISPOSITION, "attachment; filename=\"contacts.csv\""),
        ],
        body,
    )
        .into_response())
}
```

The CORS configuration exposes `Content-Disposition`, so a browser front end on another origin can read the file name.

### Streaming a file

For large files, stream the body instead of loading it. A storage disk hands you a stream that `Body::from_stream` sends chunk by chunk:

```rust title="src/invoices/controller.rs"
use http::header::{CONTENT_DISPOSITION, CONTENT_TYPE};
use navree::http::body::Body;
use navree::http::response::{IntoResponse, Response};
use navree::storage::Disk;

#[injectable]
pub struct InvoicesController {
    disk: Arc<Disk>,
}

#[controller("/invoices", version = "1")]
#[authenticated]
impl InvoicesController {
    #[get("/{id}/pdf")]
    async fn download(&self, Path(id): Path<Uuid>) -> Result<Response> {
        let stream = self.disk.get_stream(&format!("invoices/{id}.pdf")).await?;
        Ok((
            [
                (CONTENT_TYPE, "application/pdf".to_owned()),
                (CONTENT_DISPOSITION, format!("attachment; filename=\"invoice-{id}.pdf\"")),
            ],
            Body::from_stream(stream),
        )
            .into_response())
    }
}
```

With `StorageModule` in the app, a missing file is a 404 and an invalid path a 400. To let a browser download a file without your API in between, give it a signed temporary URL instead; see [file storage](/docs/digging-deeper/storage/).

## Streaming responses

`Body::from_stream` takes any stream of `Result<Bytes, E>`, so you can stream generated data the same way. Things to know:

- The request timeout (`http.timeout_secs`, 30 seconds by default) covers the time until your handler returns the response, not the time spent sending a streamed body.
- Server-sent events use the `Sse` type of `navree::http::response::sse`: it takes a stream of `Event`s, sets `Content-Type: text/event-stream` and `Cache-Control: no-cache`, and `KeepAlive` sends a comment while the stream is quiet (every 15 seconds by default). Navree doesn't compress `text/event-stream` responses, so events reach the client as they're sent.
- For pushing events to browsers, Navree's main tool is [broadcasting](/docs/digging-deeper/broadcasting/) over WebSockets.

A handler returns the `Sse` as a `Response`, for the reason in the note on `impl IntoResponse` above (the example needs `futures-util` in your dependencies):

```rust
use std::convert::Infallible;
use std::time::Duration;

use futures_util::stream;
use navree::http::response::sse::{Event, KeepAlive, Sse};
use navree::http::response::{IntoResponse, Response};

#[get("/ticks")]
async fn ticks(&self) -> Response {
    let events = stream::iter([Ok::<_, Infallible>(Event::default().event("tick").data("1"))]);
    Sse::new(events)
        .keep_alive(KeepAlive::new().interval(Duration::from_secs(15)))
        .into_response()
}
```

An error from the stream ends the response without a final chunk, so the client sees a broken connection and reconnects.

## Testing

The test client reads statuses, headers and JSON paths:

```rust title="tests/companies.rs"
let response = client
    .post("/api/v1/deals")
    .json(&json!({ "title": "Renewal", "company_id": agra, "amount_cents": 120000 }))
    .send()
    .await
    .assert_status(201)
    .assert_json_path("__type", json!("Deal"));
let location = response.header("location").unwrap();
```
