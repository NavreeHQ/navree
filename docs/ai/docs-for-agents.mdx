## Introduction

These docs are written for two readers: you, and the model working next to you. Everything you read on navree.com is also published in the form a model reads best, plain Markdown at a predictable URL, and every app you create starts with instructions for the agents that will work on it.

| What | Where | Use it to |
|---|---|---|
| The index | [`/llms.txt`](/llms.txt) | Give a model the map of the docs, one line per page. |
| Everything | [`/llms-full.txt`](/llms-full.txt) | Load the whole documentation into one context. |
| One page | `/docs/<section>/<page>.md` | Give a model exactly the page it needs. |
| One section | `/docs/<section>.md` | Give a model the list of a section's pages, with a line about each. |
| One version, as data | `/v/<version>/docs.json` | Every page split at its `##` headings, as Markdown; what [Navigator](/docs/ai/navigator/#search_docs-and-read_doc) downloads for an app on that Navree version. |
| Page actions | the top of every docs page | Copy a page, or open it in Claude or ChatGPT. |
| Project instructions | `AGENTS.md` and `CLAUDE.md` in every new app | Tell agents how your app is built before they change it. |

They are generated from the same source as the pages you are reading, at the same time, so a model never reads docs older than the site.

## Every page as Markdown

Replace the trailing slash of a docs URL with `.md` and you get the page as Markdown:

| Page | Markdown |
|---|---|
| `https://navree.com/docs/basics/validation/` | `https://navree.com/docs/basics/validation.md` |
| `https://navree.com/docs/digging-deeper/queues/` | `https://navree.com/docs/digging-deeper/queues.md` |
| `https://navree.com/docs/ai/agent-skills/` | `https://navree.com/docs/ai/agent-skills.md` |

A section's own page works the same way: `https://navree.com/docs/basics/` is `https://navree.com/docs/basics.md`, a list of the section's pages with their descriptions.

The Markdown starts with the page's title as a heading and its description, then the body as written: headings, tables, and code blocks with their language and file name. The site's components become plain Markdown, so nothing is lost on the way: a callout becomes a block quote that starts with its kind ("Note", "Tip", "Warning"), each tab becomes a titled section, steps become numbered headings, link cards a list of links, a file tree a text block and a diagram one sentence that describes it. The files are served as `text/markdown`, with no navigation, scripts or styling around them.

Point your agent at the page for the task:

```text
Read https://navree.com/docs/digging-deeper/queues.md, then add a queued job
that exports a company's contacts to CSV and mails the requester a link.
```

## llms.txt

[`/llms.txt`](/llms.txt) follows the [llms.txt](https://llmstxt.org/) convention: a short description of Navree, its key facts (name, license, version, install command), the main pages of the site, then one line per docs page, in the order of the sidebar, linking the page's Markdown with its one-sentence description. Each section starts with a line for the section's own page:

```text title="https://navree.com/llms.txt"
# Navree

> The complete application framework for Rust. The backend, the screens and the tools to run them, in one modular, AI-native framework.

## Key facts

- Name: Navree
- Category: The complete application framework for Rust.
- License: MIT OR Apache-2.0 (free and open source, no paid tiers)
- Version: 1.0.0 (the first release; from the workspace Cargo.toml)
- Install: `cargo install navree-cli`, then `navree new blog`
...

## Main pages

- [Home](https://navree.com/): What Navree is, what comes in the box, and how to start.
- [Navree UI](https://navree.com/ui/): Typed Rust components rendered on the server: how it works, every component with a live preview, what comes next.
...

## Prologue

- [Prologue: all pages](https://navree.com/docs/prologue.md): What Navree is, what 1.0 ships, what comes next, and how to report a bug or send a change.
- [Introduction](https://navree.com/docs/prologue/introduction.md): What Navree is, the ideas it is built on, what comes in the box, who it's for and how to read these docs.
...

## Getting started

- [Getting started: all pages](https://navree.com/docs/getting-started.md): Install the CLI, build your first app, and learn how an app is configured, laid out, started and deployed, or bring an existing product or design.
- [Installation](https://navree.com/docs/getting-started/installation.md): Install Rust and the `navree` CLI, create an app with `navree new`, and run it with `navree dev`.
- [Your first app](https://navree.com/docs/getting-started/your-first-app.md): Build a small task-list API with a model, a migration, validation, JWT authentication, access rules and feature tests, from `navree new` to green tests.

...
```

The index ends with an "Optional" section: the longer files (`/llms-full.txt`, the sitemap and the changelog feed), the address of `/skills/index.json`, which lists every [agent skill](/docs/ai/agent-skills/), and one line per skill, linking its `SKILL.md` on navree.com.

An agent that starts from `llms.txt` reads the index (a few thousand tokens), picks the pages that matter for the task and fetches only those. That is the best default: small, current and specific.

## llms-full.txt

[`/llms-full.txt`](/llms-full.txt) is every page's Markdown in one file, in sidebar order, each page starting with its title and URL. A section's own page comes before the section's pages. Use it when you want the model to hold the whole framework at once: loading it into a project's knowledge in a chat app, or asking broad questions ("Which modules does an app with workspaces, queues and real time need, and in what order?").

It is large, the size of a book. For a coding task in your editor, the index and a few pages are faster and cost less; for a long design conversation, the full file saves the model from fetching page after page.

## Page actions

Every docs page has actions next to its title:

| Action | What it does |
|---|---|
| **Copy page** | Copies the page's Markdown to your clipboard, to paste into any chat or agent. |
| **View as Markdown** | Opens the page's `.md` URL. |
| **Open in Claude** | Opens a new Claude conversation that reads the page, ready for your question. |
| **Open in ChatGPT** | The same, in ChatGPT. |

"Open in" starts the conversation with a prompt that names the page's Markdown URL and asks the assistant to read it first, so your first message can be the question itself: "How do I make this job unique per company?"

## AGENTS.md and CLAUDE.md

`navree new` writes two files at the root of every app, next to `README.md`:

<FileTree title="navree new crm">{`
  AGENTS.md *       # conventions for every coding agent
  CLAUDE.md *       # imports AGENTS.md for Claude Code
  Cargo.toml
  README.md
  config/
  src/
  tests/
`}</FileTree>

**`AGENTS.md`** is the project's instructions for coding agents, in the format most agents read on their own. It is written for the app it lives in, with the app's name, and covers:

- **Layout**: what lives in `config/`, `src/app.rs`, `src/abilities.rs`, `src/modules/<name>/`, `tests/` and `storage/` (and `web/` for apps created with `--ui next`, `src/ui/` and `src/modules/customers/` for apps created with `--ui navree`).
- **Commands**: `navree dev`, `cargo test`, `cargo clippy --all-targets -- -D warnings`, `cargo fmt`, `navree check`, `navree routes`, `navree migrate` and `navree list`.
- **Generators**: which `navree make:*` command to run for each kind of code, and the marker comments (`// navree:modules`, `// navree:wire`, `// navree:policies`) they register at.
- **Conventions**: deny-by-default routes and the access attributes, modules and injected services, validated DTOs, the error shape and `AppError` helpers, the unit of work and models, migrations, configuration and secrets, and tests with `TestApp`.
- **Before you finish**: format, lint and test, and fix everything they report.
- **Documentation and skills**: these docs, `llms.txt`, the Markdown pages and how to install the [agent skills](/docs/ai/agent-skills/).

**`CLAUDE.md`** is for Claude Code, which reads that file name. It imports `AGENTS.md` instead of repeating it, so every agent reads the same instructions:

```text title="CLAUDE.md"
@AGENTS.md

The conventions for coding agents in crm live in AGENTS.md, imported above; keep them there so every agent reads the same file.
```

### Making them yours

The generated `AGENTS.md` describes Navree's conventions. Add your team's: the domain words agents should use, the modules that are off limits, how you name migrations, which [Navigator](/docs/ai/navigator/) tools to use before changing routes or the schema. Keep it short and specific; agents read it at the start of every session, and a rule written down there beats the same rule explained again in every prompt.

Edit `AGENTS.md`, not `CLAUDE.md`. Claude Code follows the import, and every other agent reads `AGENTS.md` directly.

For an app that doesn't have these files, such as one you built by hand, run `navree new` for a scratch app of the same kind and copy its `AGENTS.md` and `CLAUDE.md` into your project, changing the name.

## Choosing what to give your agent

| Situation | Give it |
|---|---|
| Every session in a Navree app | `AGENTS.md` (automatic) and the [agent skills](/docs/ai/agent-skills/) |
| A task that touches one feature | The feature's page as `.md` |
| A question about your running app | [Navigator](/docs/ai/navigator/): routes, schema, logs, configuration |
| An agent with web access and no skills | `https://navree.com/llms.txt` |
| A long design discussion in a chat app | `https://navree.com/llms-full.txt` |

Skills, `AGENTS.md` and Navigator work together: `AGENTS.md` says how this app is built, a skill says how to do this kind of task, Navigator says what the app looks like right now, and the docs say everything else.
